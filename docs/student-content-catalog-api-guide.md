# Student content and catalog API guide

This guide explains the read APIs used to browse the catalogue, decide whether a
student can open something, retrieve a content item, and obtain a short-lived
asset URL. Examples are based on
`reports/api-tests/api-2026-08-05T17-42-52-691Z.json`.

The IDs and titles in that report were generated by the API journey and may no
longer exist. Signed URL tokens have deliberately been replaced with
`<signed-token>`: clients must always use the complete URL returned by the API,
not construct one themselves.

## At a glance

```
public catalogue                 student catalogue
subjects → courses → chapters    student grade → subjects → courses → chapters
                  → lessons → sections                       → lessons → sections
                               ↓                                         ↓
                         content previews                          access + lock state
                               ↓                                         ↓
              public item / public asset URL       entitled item / entitled asset URL
```

There are two related but different concepts:

- **Catalogue visibility**: whether a published subject, course, or item is
  discoverable. Public catalogue routes expose this.
- **Delivery access**: whether the student can read protected content or obtain
  a protected asset URL. Student routes calculate this from the student's active
  entitlements. A catalogue preview is not permission to deliver paid content.

Use `Authorization: Bearer <student-access-token>` for every `student/*` route.
The `catalog/*` routes are public; a token is optional there. All examples use
`$BASE_URL` as the API origin.

## Content delivery and assets

### Get a published content item

`GET /api/v1/catalog/content-items/{id}` returns the full *published and
publicly accessible* delivery item. It is a public route. Use it after a
catalogue preview indicates an item is public.

```bash
curl "$BASE_URL/api/v1/catalog/content-items/cmsgdjl7s01mar3014yo8tchq"
```

### Get a content item a student can access

`GET /api/v1/student/content-items/{id}` is the delivery route for a signed-in
student. It enforces the item's effective access rule (including its ancestors)
and the student's entitlement. It returns the same core item data as the public
route plus that student's item-level completion state.

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/content-items/cmsgdjl7s01mar3014yo8tchq"
```

The corresponding successful response in the log was:

```json
{
  "id": "cmsgdjl7s01mar3014yo8tchq",
  "type": "PDF",
  "title": "Attachment content journey-20260805173810-49ee-127",
  "placement": {
    "courseId": "cmsgdexy60169r3013al8lihd",
    "chapterId": null,
    "lessonId": null,
    "sectionId": null,
    "sortOrder": 4
  },
  "primaryAsset": {
    "id": "cmsgdi7vk01dlr3010af8vx0e",
    "kind": "PDF",
    "filename": "phase9-journey-20260805173810-49ee-resource.pdf",
    "mimeType": "application/pdf",
    "sizeBytes": 2634119
  },
  "attachments": [{ "id": "cmsgdi7vk01dlr3010af8vx0e", "kind": "PDF", "sortOrder": 1 }],
  "progress": { "completed": false, "completedAt": null }
}
```

For a text item, `textBody` is populated and `primaryAsset`/`attachments` can
be `null`/`[]`. A student without access receives an authorization error rather
than a preview of protected body data.

### Obtain an asset URL

Both asset routes first verify that `assetId` is attached to `contentItemId`.
They return a temporary delivery credential, not the asset bytes.

| Route | Who can call it | When to use it |
| --- | --- | --- |
| `GET /api/v1/catalog/content-items/{contentItemId}/assets/{assetId}/access` | Anyone | The content item is public. |
| `GET /api/v1/student/content-items/{contentItemId}/assets/{assetId}/access` | Authenticated `STUDENT` | The item is protected and the student is entitled; it also works for public items. |

Public PDF request and response from the report:

```bash
curl "$BASE_URL/api/v1/catalog/content-items/cmsgdg5vj018fr301zyy5ishc/assets/cmsgdffoz018br30102wrc6zq/access"
```

```json
{
  "url": "https://edu-private-pull-zone.b-cdn.net/assets/pdf/439dbf0e-...-lesson.pdf?token=<signed-token>&expires=1785951864",
  "expiresAt": "2026-08-05T17:44:24.655Z"
}
```

Entitled-student PDF request and response:

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/content-items/cmsgdid5n01dpr301o7fbxc8v/assets/cmsgdi7vk01dlr3010af8vx0e/access"
```

```json
{
  "url": "https://edu-private-pull-zone.b-cdn.net/assets/pdf/06dcf962-...-resource.pdf?token=<signed-token>&expires=1785951992",
  "expiresAt": "2026-08-05T17:46:32.395Z"
}
```

Videos use the same student asset endpoint but return `embedUrl`, which should
be used in a video player/iframe, rather than `url`:

```json
{
  "embedUrl": "https://iframe.mediadelivery.net/embed/712744/fc1df670-...?token=<signed-token>&expires=1785951994",
  "expiresAt": "2026-08-05T17:46:34.000Z"
}
```

Do not cache these URLs past `expiresAt`. On expiry, request a new one from the
same access endpoint. The report also recorded HTTP 403 after an entitlement
was revoked, confirming that the student endpoint checks access at request time.

## Public catalogue (`/catalog`)

These endpoints describe published content across all grades. They are suitable
for a catalogue/storefront. List endpoints use page-number pagination:
`page` is one-based and `limit` is 1–100 (default 20). Child-list endpoints use
opaque cursor pagination: `cursor` and `limit` (default 20). Never decode or
manufacture a cursor; send `pageInfo.nextCursor` back unchanged.

### Subjects and courses

**`GET /api/v1/catalog/subjects`** lists published subjects. Optional query:
`academicGradeId`, `page`, `limit`.

```bash
curl "$BASE_URL/api/v1/catalog/subjects?academicGradeId=cmsgdexml0161r301l6a8vj7u"
```

### Hierarchy and content previews

| Purpose | Route |
| --- | --- |
| Chapters directly in a course | `GET /api/v1/catalog/courses/{id}/chapters` |
| Lessons directly in a chapter | `GET /api/v1/catalog/chapters/{id}/lessons` |
| Sections directly in a lesson | `GET /api/v1/catalog/lessons/{id}/sections` |
| Content placed directly on a node | `GET /api/v1/catalog/{resource}/{id}/content-items` |

For the generic content route, `resource` must be exactly one of `courses`,
`chapters`, `lessons`, or `sections`. “Directly” matters: content on a lesson is
not repeated in its course or chapter response.

```bash
curl "$BASE_URL/api/v1/catalog/courses/cmsgdexy60169r3013al8lihd/chapters?limit=20"
curl "$BASE_URL/api/v1/catalog/chapters/cmsgdey37016dr301ekdz58iy/lessons?limit=20"
curl "$BASE_URL/api/v1/catalog/lessons/cmsgdey9i016hr301x2u98mtq/sections?limit=20"
curl "$BASE_URL/api/v1/catalog/courses/cmsgdhpnu019er3017n86frdd/content-items?limit=20"
```

from the report:

## Student catalogue, library, and entitlements (`/student`)

These are authenticated `STUDENT` routes. Every catalogue result is restricted
to the student's assigned academic grade. The student catalogue is the right
source for UI lock states and purchase prompts; do not try to reproduce its
access calculation in the client.

### Catalogue summary and subjects

**`GET /api/v1/student/catalog`** is the lightweight starting point. It returns
the current grade and counts of published nodes in that grade.

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" "$BASE_URL/api/v1/student/catalog"
```

```json
{
  "academicGrade": {
    "id": "cmsgdhqzg019wr301kyrzrtwo",
    "title": { "ar": "Student catalog grade journey-20260805173810-49ee-54", "en": "Student catalog grade journey-20260805173810-49ee-54" },
    "slug": "student-catalog-grade-journey-20260805173810-49ee-55",
    "description": { "ar": null, "en": null },
    "sortOrder": 92,
    "coverAssetId": null
  },
  "summary": { "subjects": 1, "courses": 1, "chapters": 2 }
}
```

**`GET /api/v1/student/catalog/subjects`** lists the published subjects in that
grade. It accepts `page` and `limit` just like the public subject list.

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/catalog/subjects?page=1&limit=20"
```

```json
{
  "data": [{ "id": "cmsgdhr5801a0r301g3rreijn", "title": "Student catalog subject journey-20260805173810-49ee-56", "slug": "student-catalog-subject-journey-20260805173810-49ee-57", "description": null, "sortOrder": 1, "coverAssetId": null }],
  "meta": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

### Courses and access state

**`GET /api/v1/student/catalog/subjects/{subjectId}/courses`** lists courses
within both the specified subject and the student's grade. It accepts `page`
and `limit`. Each course has an effective `access` object and `isLocked`.

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/catalog/subjects/cmsgdhr5801a0r301g3rreijn/courses"
```

```json
{
  "data": [{
    "id": "cmsgdhrax01a4r301rca5izra",
    "title": "Student catalog paid course journey-20260805173810-49ee-58",
    "slug": "student-catalog-paid-course-journey-20260805173810-49ee-59",
    "sortOrder": 1,
    "coverAssetId": null,
    "access": { "state": "PURCHASABLE", "price": { "amountMinor": 20000, "currency": "EGP" } },
    "isLocked": true
  }],
  "meta": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

**`GET /api/v1/student/catalog/courses/{courseId}`** gets a single course in
the student's grade, with the same `access` and `isLocked` fields and its
`subject`. It is useful for a course landing page; load chapters separately.

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/catalog/courses/cmsgdhrax01a4r301rca5izra"
```

Representative response (the report's course object has this exact shape):

```json
{
  "id": "cmsgdhrax01a4r301rca5izra",
  "title": "Student catalog paid course journey-20260805173810-49ee-58",
  "slug": "student-catalog-paid-course-journey-20260805173810-49ee-59",
  "description": null,
  "sortOrder": 1,
  "coverAssetId": null,
  "access": { "state": "PURCHASABLE", "price": { "amountMinor": 20000, "currency": "EGP" } },
  "isLocked": true,
  "subject": { "id": "cmsgdhr5801a0r301g3rreijn", "title": "Student catalog subject journey-20260805173810-49ee-56", "slug": "student-catalog-subject-journey-20260805173810-49ee-57", "sortOrder": 1, "coverAssetId": null }
}
```

Access states should be rendered as follows:

| State | Meaning for the client |
| --- | --- |
| `PUBLIC` or `FREE` | The student can open it. |
| `ENTITLED` | The student can open it using the listed entitlement; `expiresAt` may be present. |
| `PURCHASABLE` | Show price/purchase UI; delivery is locked. |
| `LOCKED` | Delivery is locked and no purchasable price is available at that node. |

After a chapter entitlement was granted in the report, the same chapter changed
from `PURCHASABLE`/`isLocked: true` to:

```json
{
  "access": {
    "state": "ENTITLED",
    "entitlementId": "cmsgdhv2401bhr3016xrc5ghp",
    "expiresAt": null,
    "price": { "amountMinor": 20000, "currency": "EGP" }
  },
  "isLocked": false
}
```

### Student hierarchy and student content previews

| Purpose | Route |
| --- | --- |
| Chapters in a grade-scoped course | `GET /api/v1/student/catalog/courses/{courseId}/chapters` |
| Lessons in a grade-scoped chapter | `GET /api/v1/student/catalog/chapters/{chapterId}/lessons` |
| Sections in a grade-scoped lesson | `GET /api/v1/student/catalog/lessons/{lessonId}/sections` |
| Previews placed directly on a node | `GET /api/v1/student/catalog/{resource}/{id}/content-items` |

All accept optional cursor-pagination query parameters, `cursor` and `limit`.
For the generic route, `resource` is one of `courses`, `chapters`, `lessons`,
or `sections`. The request pattern is the public equivalent plus the bearer
token:

```bash
curl -H "Authorization: Bearer $STUDENT_TOKEN" \
  "$BASE_URL/api/v1/student/catalog/courses/cmsgdhrax01a4r301rca5izra/chapters?limit=20"

  "$BASE_URL/api/v1/student/catalog/chapters/cmsgdhrgu01a8r301sbh8u018/content-items?limit=20"
```

## Recommended client sequence

1. For an anonymous storefront, browse `/catalog`; use its `accessType` to
   explain the offer, then use public content only where appropriate.
2. After student login, start at `/student/catalog`, browse its hierarchy, and
   render `access`/`isLocked` exactly as returned.
3. On an unlocked item, request `/student/content-items/{id}`. This is the
   authoritative access check and returns student progress.
4. If the item has `primaryAsset` or `attachments`, request the matching
   student asset `/access` endpoint immediately before opening/downloading it.
5. Use `/student/library` for a cross-grade “My library” screen and
   `/student/entitlements` for the underlying active grants.

Common causes of an error are a non-published ID, a hierarchy record belonging
to another grade, an unsupported `resource`, an invalid cursor, a detached asset
ID, or a missing/expired/revoked entitlement. Treat `403` from a student
delivery/asset route as a prompt to refresh the catalogue/access state, not as a
reason to reuse an old signed URL.
